# ADR-001：工具通过 MCP 暴露，而不是硬编码 function call

## 状态
已采纳（2026-11）

## 背景与约束
- Agent 需要调用三类工具：读文件、跑测试、查 issue
- 后续会持续加工具（预计 10+），且部分工具要给别的 Agent 复用
- 单人开发，维护成本要低

## 选项
A. 在每个 Agent 里直接写 function call 的 schema 和实现
B. 用 MCP Server 统一暴露，Agent 侧只做协议接入
C. 自研一套工具注册中心

## 决策
选 B。判据：工具的**定义**和**使用**分离；换模型、换 Agent 框架都不用重写工具层。

## 后果
- 正面：工具一次编写、多处复用；权限边界可以收在 MCP Server 这一层
- 负面：多一次进程间调用（本地 stdio 可忽略，远程则要算延迟）；调试链路变长
- 缓解：MCP Server 本地 stdio 启动，工具内部加耗时日志

## 如果重来
会先把"工具的错误返回格式"定成统一结构（现在每个工具各写各的），后面加工具时省了很多对齐成本。
