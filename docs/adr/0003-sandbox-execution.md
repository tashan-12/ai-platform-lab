# ADR-003：执行放沙箱，而不是同集群容器

## 状态
已采纳（2026-11）；**当前实现为"受限本地子进程"，托管沙箱是目标态**（见"实现状态"）

## 背景与约束
- 会在目标仓库里跑命令，被跑的对象是**不可信输入**
- 本机开发，没有可用 K8s、没有云沙箱账号
- 需要可复现：同一份代码跑两次，结论一致
- 单人维护，安全机制必须"看得懂、改得动"

## 选项
A. 本机 subprocess 直接跑（不隔离）
B. 受限 subprocess：白名单 + 超时 + 最小环境变量 + 工作目录收敛
C. 托管沙箱（e2b 这类云沙箱）
D. 云上 K8s Job / 自建 microVM

## 决策
**现在选 B，目标态是 C。**

判据：
- A 不可接受——等于把任意代码拉到宿主机上执行；
- C/D 在"没有账号、没有集群"的约束下交付不了，硬上会让仓库"clone 下来跑不起来"；
- B 是唯一"当天就能落地、且能挡住大部分事故"的选项。

B 挡得住什么、挡不住什么，必须写清楚：

| 能挡住 | 挡不住 |
|---|---|
| 命令注入（shlex 切分 + 不走 shell） | 恶意代码读取同一用户的家目录文件 |
| 越权执行（命令白名单） | 恶意代码消耗全部 CPU / 内存 |
| 跑错目录（cwd 收敛到工作区） | 恶意代码访问网络 |
| 环境变量泄漏（只透传 6 个） | 内核漏洞提权 |
| 无限运行（超时 + 输出截断） | 写入工作区以外可写的路径 |

**结论：B 只适合"跑自己写的、或用户明确提供的代码"，不适合多租户对外服务。**

## 后果
- 正面：零外部依赖；结论可复现；出问题看得懂日志
- 负面：隔离强度弱，不能对外承诺"安全执行"
- 缓解：在 README 和工具描述里如实标注"受限本地执行"，不做安全承诺

## 什么时候必须升级到 C/D
出现任意一条，就必须换：

1. 要执行**第三方**提交的代码（不是自己或同事写的）；
2. 对外提供多租户服务；
3. 代码会访问网络或需要出网白名单；
4. 需要按调用计费 / 配额。
