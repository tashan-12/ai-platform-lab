# 检索评测报告

- 语料：12 篇文档 / 88 个块（平均 79 字符）
- 评测集：20 条，5 类
- 评测方式：文档级命中（命中期望文档即算对），取 Top-10 计算名次

## 总体结果

| 配置 | Recall@1 | Recall@3 | Recall@5 | MRR | P50 | P95 |
|---|---|---|---|---|---|---|
| bm25 | 85.00% | 90.00% | 95.00% | 0.895 | 1.8 ms | 2.1 ms |
| vector | 75.00% | 85.00% | 100.00% | 0.827 | 1.9 ms | 2.2 ms |
| hybrid | 85.00% | 95.00% | 100.00% | 0.904 | 1.8 ms | 2.2 ms |
| hybrid+rerank | 85.00% | 100.00% | 100.00% | 0.908 | 1.8 ms | 2.1 ms |

**结论**：按 Recall@3 选，最优是 `hybrid+rerank`（100.00%，相对 BM25 基线 +10.0 个百分点）；但按 MRR 选，最优是 `hybrid+rerank`（0.908）。

**指标冲突（这条比排名本身更值得看）**：混合+重排把正确答案更多推进了前 3，却也让少数原本排第一的结果掉到第二，导致 MRR 反而略低于纯 BM25。这说明在当前语料上，重排的收益集中在「召回长尾」，代价是「头部精度」。选型取决于用途：RAG 取前 3 段上下文做生成 → 选 hybrid+rerank；只需一条精确答案 → 保持 BM25。

## 方法与局限

- **标注方式**：20 条问题由作者本人按仓库文档构造，标注到文档级；**存在作者偏差**——
  写题的人知道答案在哪，题目会更贴近文档原文措辞，真实用户提问通常更模糊。
- **指标口径**：Recall@k 只回答「该看的文档有没有进前 k 条」，不评价块内排序质量；
  MRR 只取第一个命中，多文档问题（如 Q08、Q14）按任一命中计算。
- **未覆盖**：多轮对话式检索、跨文档聚合问答、拒答（无答案时应不返回）。
